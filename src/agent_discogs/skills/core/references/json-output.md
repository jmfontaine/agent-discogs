# JSON Output

The JSON is a compact projection of what the text view shows, with refs as strings you can pass straight back: `{"ref":"@r847868","artists":[{"ref":"@a3857","name":"Nine Inch Nails"}],"labels":[{"ref":"@l647","name":"Nothing Records","catno":"92346-2"}],"master":"@m3719",...}`. Each release, master, artist, label, and search result also carries `url`, its absolute Discogs web page (`"url":"https://www.discogs.com/release/847868-Nine-Inch-Nails-The-Downward-Spiral"`): use it when a person needs a link. Text output never prints it; which rows lack one: `--json` under `get` flags. Empty fields are omitted: test for the key, not for null. `get credits --json` is grouped by role, `{"Producer":[{"ref":"@a...","name":"...","tracks":"1, 2"}],...}`, the same grouping as the text. A page of a listing comes wrapped in `{"pagination":{...},"results":[...]}`; `page`, `total_items` and `total_pages` are always present (totals `null` only when a scan stopped before reading any page), filtered lists always carry `filtered`, `capped` and `pagination.next_cursor` for `--after` (`null` when nothing remains), and a capped list adds `stop_reason` (`max_requests` or `rate_limited`) and, when Discogs sent one, `retry_after`.

Two documents are not pages and have no `pagination`: `get collection --random` (`{"random":{...},"results":[...]}`, see the collection skill) and `search release ... --added-since`, the whole window at once as `{"complete","total","results"}`. `complete` is `false` when `--max-requests` stopped it; `total` counts rows after `--release-type`, before `--limit`, which cuts `results`. A row is `ref`, `url`, `title` (`Artist - Title`), `year`, `country`, `label`, `catno`, `formats` (a string, as `get release` gives it, not a search row's `format` array), `added` (RFC 3339) and `master`; `--full` rows are SDK release records.

`--full` is the complete record, normalized: consistent field names (`catalog_number`, not `catno`; `extra_artists`, not `extraartists`; `name_variation`, not `anv`; a track's `type`, not `type_`), absolute search-result `uri`s, RFC 3339 timestamps with an offset (`"date_added":"2005-01-03T23:17:26-08:00"`), and `null` for a timestamp that is absent or does not parse. Fields the SDK does not model appear as Discogs sends them. Unlike the projection, it keeps empty fields, as `null` when unset.

On a UTF-8 stdout, non-ASCII text is literal (`"title":"無罪モラトリアム"`); on any other encoding it is `\uXXXX`-escaped. Control, bidi, and line-separator characters (U+0080–U+009F, U+061C, U+200E/F, U+202A–U+202E, U+2066–U+2069, U+2028/9), invisible ones (U+200B–U+200D, U+2060–U+206F, U+FEFF, the tag characters U+E0000–U+E007F) and lone surrogates are always escaped, a character above U+FFFF as its `\uXXXX\uXXXX` surrogate pair. The escaping is lossless: a JSON parser returns every string unchanged.
