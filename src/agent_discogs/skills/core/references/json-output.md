# JSON Output

`search`, `get`, `tracks`, and `price` support `--json`, and so do `cache clear` (`{"cleared":true}`, or the error envelope) and `skills list` (`[{"name","description","version"}]`, one object per bundled skill); `status` and the rest of `skills` are text-only. The JSON is a compact projection of what the text view shows, with refs as strings you can pass straight back: `{"ref":"@r847868","artists":[{"ref":"@a3857","name":"Nine Inch Nails"}],"labels":[{"ref":"@l647","name":"Nothing Records","catno":"92346-2"}],"master":"@m3719",...}`. Each release, master, artist, label, and search result also carries `url`, its absolute Discogs web page (`"url":"https://www.discogs.com/release/847868-Nine-Inch-Nails-The-Downward-Spiral"`): use it when a person needs a link. Text output never prints it. `get versions` / `get releases` rows carry one only when Discogs includes a link (`uri`) in the row (it does not today), and the release facets (`tracks`, `price`, `get credits`, `get identifiers`) never do: use `get release @r... --json` for the link. Empty fields are omitted: test for the key, not for null. `get credits --json` is grouped by role, `{"Producer":[{"ref":"@a...","name":"...","tracks":"1, 2"}],...}`, the same grouping as the text. Lists come wrapped in `{"pagination":{...},"results":[...]}`; `page`, `total_items` and `total_pages` are always present (totals `null` only when a scan stopped before reading any page), filtered lists always carry `filtered`, `capped` and `pagination.next_cursor` for `--after` (`null` when nothing remains), and a capped list adds `stop_reason` (`max_requests` or `rate_limited`) and, when Discogs sent one, `retry_after`.

`--full` is the complete record, normalized: consistent field names (`catalog_number`, not `catno`; `extra_artists`, not `extraartists`; `name_variation`, not `anv`; a track's `type`, not `type_`), absolute search-result `uri`s, RFC 3339 timestamps with an offset (`"date_added":"2005-01-03T23:17:26-08:00"`), and `null` for a timestamp that is absent or does not parse. Fields the SDK does not model appear as Discogs sends them. Unlike the projection, it keeps empty fields, as `null` when unset.

On a UTF-8 stdout, non-ASCII text is literal (`"title":"無罪モラトリアム"`); on any other encoding it is `\uXXXX`-escaped. Control, bidi, and line-separator characters (U+0080–U+009F, U+061C, U+200E/F, U+202A–U+202E, U+2066–U+2069, U+2028/9) and lone surrogates are always escaped. The escaping is lossless: a JSON parser returns every string unchanged.
