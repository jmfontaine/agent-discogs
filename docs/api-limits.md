# What the Discogs API cannot answer

Some questions have no endpoint or field in the Discogs API, so no agent-discogs command can answer them; the last row is different: the API can write, but agent-discogs only reads. This page lists them, with what to do instead. The bundled `core` skill (`agent-discogs skills get core`) carries the same table.

`price` costs 3 requests per ref (the release, its price suggestions, its Marketplace stats), in text and `--json`. Discogs serves price suggestions only to an account with seller settings filled out. Without them, `price` fails with `seller_settings_required`. `get release @r... -c` then gives the count for sale and the lowest price only (`Market: N for sale from X`, a bare amount in the account's currency; `market` under `--json`), and no per-condition value exists.

| Question | The API | Instead |
|---|---|---|
| What did this release sell for? Sales or price history? | No endpoint for a release's sales or price history. | `price @r...` gives Discogs' suggested price per condition (seller settings needed), the count for sale and the lowest price. Without seller settings, `get release @r... -c` gives the count and the lowest price only. `get release @r... --json` has `url`, the release's page on discogs.com: sales history, if Discogs shows it, is only there. |
| What is this one record worth? Median value per record? | Price suggestions per condition; no per-record value. | `price @r...`. Without seller settings it fails with `seller_settings_required`, and `get release @r... -c` gives the count and the lowest price only. The collection value is one estimate for the whole collection and cannot be split per record. |
| What is this folder worth? | One value, for the whole collection. | [`get collection --value`](commands.md#--value) values the whole collection and takes no filter (`invalid_argument` before any request). For a subset, run `price` on each release and add the amounts yourself, 3 requests per release. Without seller settings `price` fails with `seller_settings_required`, and no per-condition value, so no subset estimate, exists. |
| Who has copies of this release for sale? Which listings, at what condition, from which country? | A count and one lowest price per release, not the copies. | `get release @r... -c` or `price @r...` for the count and the lowest price (`get release` needs no seller settings; without them `price` fails with `seller_settings_required`). For a seller you already know, [`get inventory <username>`](commands.md#inventory) lists their listings and filters on condition, sleeve, ships-from and price. For the copies of one release, open its Marketplace page on discogs.com. |
| Alert me when a release is listed or a price drops. | No alerts, saved searches or notifications. The CLI never waits or polls. | Run the check again later: `get wantlist --for-sale --max-requests 60` for the wantlist, `search release ... --added-since YYYY-MM-DD` for new releases. Each run costs requests. Repeats within an hour come from the cache; add `--fresh` for current numbers. |
| Find sellers (by country, size, rating), or the sellers of a release. | No endpoint lists or searches sellers. One seller's inventory needs their username. | `get inventory <username>`, with a username from the user or from a page on discogs.com. |
| Tempo, BPM or musical key of a track | Track entries carry position, type, title, duration and credits; no tempo or key field. | Say so; do not estimate. Another source has to supply them. |
| Add to my collection, wantlist or a list; rate; edit a release; list for sale | agent-discogs only reads: it sends Discogs no write request and has no flag for one. | Do it on discogs.com. `get owned`, `--owned`, `get wantlist` and `get collection` read the result afterwards. |

## Why, row by row

- **Sales history.** The Marketplace section of the API reference has, for prices, only the price suggestions (`GET /marketplace/price_suggestions/{release_id}`), the release statistics (`GET /marketplace/stats/{release_id}`: copies for sale, lowest price, blocked from sale) and the fee calculators, which take a price you already have. Its order endpoints cover only the authenticated seller's own orders.
- **One record's worth.** The price suggestions are per condition, in the account's selling currency. No endpoint gives a single value or a median for one release.
- **A folder's worth.** `GET /users/{username}/collection/value` takes only the username and returns the minimum, median and maximum of the whole collection. Nothing scopes it to a folder or a set of records. See [`--value`](commands.md#--value).
- **Who sells a release.** The release statistics are the number of copies for sale and one lowest price across every condition and location. No endpoint lists the copies for sale of a release, which is also why [`get wantlist --for-sale`](commands.md#--for-sale) cannot filter on condition, sleeve, location or shipping.
- **Alerts.** The API is request and response only: it has no subscription, saved-search or notification endpoint. agent-discogs answers one request at a time and never schedules a rerun.
- **Finding sellers.** The inventory endpoint (`GET /users/{username}/inventory`) needs a username, and no endpoint searches users or sellers. This is the limit under "What it cannot do" in [`get inventory`](commands.md#inventory).
- **Tempo and key.** A release's `tracklist` entries have `position`, `type_`, `title`, `duration` and, for some tracks, `extraartists`. The API has no audio-analysis field.
- **Writes.** The API has write endpoints (collection folders and ratings, the wantlist, Marketplace listings), but agent-discogs uses none of them. It neither adds, moves, rates nor removes [collection](commands.md#collection) records, and neither adds nor removes [wants](commands.md#wantlist).
